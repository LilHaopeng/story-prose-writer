# 正典守恒、防幻觉与六维审校清单

在每章初稿生成后、或对已有正文执行 `audit / revise` 时读取。目标是降低设定幻觉（Hallucination）、主线偏离（Plot Drift）、人物崩坏（OOC）与跨章连续性错误的风险；核对依赖材料覆盖和人工判断，不宣称彻底杜绝。

## 1. 防幻觉与防偏离的四条铁律（Anti-Hallucination & Anti-Drift）

1. **设定零虚构原则（Zero Unregistered Lore）**：
   - 正文中的关键货币面额、官职品级、地理距离、法术/科技代价、宗门/机构名称应有设定、大纲或用户提供的等价材料依据；涉及关键事实且依据不足时标记未知并上报。
   - 当场景需要一个次要背景细节（如茶馆名字、街道铺面、普通兵刃）时，只能使用符合该世界创作锚点（`00_创作锚点.md`）的普通泛称或临时生活物件，**严禁随手编造听起来像核心设定的专有名词、新功法体系、新政令或跨阶级特权**。
2. **因果节点闭环原则（Mandatory Beat Fulfillment）**：
   - `细纲_第N章.md` 中列出的 `人物目标`、`阻碍`、`决策`、`代价`、`状态变化` 与 `新信息` 是本章的必达契约。
   - 正文不能因为写嗨了就把下章才该发生的冲突提前写完（抢戏），也不能写满字数却还没走到本章的核心决策（拖戏）。
3. **代价守恒原则（Cost Conservation）**：
   - 世界观 `RULE-NNN` 规定的限制与代价、大纲规定的 `Cost`，在正文中必须实打实地发生并留下痕迹。不能在大纲里写“惨胜重伤”，到了正文里主角拍拍灰尘就接着跟人谈笑风生。
4. **冲突上报而非私改（Escalate, Never Silently Mutate）**：
   - 如果在写正文时发现大纲预设的动作违反了世界观硬规则（如大纲让角色一夜跨越三千里，但世界观规定该时代最快驿马需五日），主笔不得自己编一个“传送符”圆过去，而应立即指出该冲突，提供“改时间线”或“改交通工具/前置铺垫”两个选项请用户确认。

## 2. 交稿前六维自检表（6-Dimension Prose Audit）

每章写完后，逐项核对以下六个维度：

| 维度 | 核心核对问题 | 阻断级别 | 修复动作 |
|---|---|---|---|
| **D1 大纲对齐** | 本章的 `Choice -> Cost -> New State` 是否完整演出来了？章纲明确要求的戏眼或结尾安排（如有）是否落地？有无抢写下一章剧情或漏掉本章必交信息？ | **S0 阻断** | 补写缺失节拍，或截断越界抢写的后续剧情 |
| **D2 世界观正典** | 是否触发了 `RULE/INST` 的禁止假设？货币购买力、称谓礼仪、技术/力量消耗是否与设定集一致？有无私自发明新设定？ | **S0 阻断** | 删改违规设定，将超模手段替换为符合规则的代价博弈 |
| **D3 连续性与防吃书** | 与上一章 `章节交接.md` 的时间、地点、天气、伤势、剩余资金/道具是否严丝合缝？人物是否突然瞬移或伤势自动痊愈？ | **S1 严重** | 修正场景过渡、补上伤势/道具的持续影响描写 |
| **D4 视角与防剧透** | 是否遵守本书已选视角与揭示节奏？限知 POV 角色是否获知了不可能知道的信息，旁白是否越界泄露反转（如有）？ | **S1 严重** | 按已确认的视角修正越界；限知叙述可改为可见痕迹与主观判断，全知叙述遵守揭示安排 |
| **D5 人物与声口** | 角色的决定是否符合其决策依据与底线？遮住名字读对白，声口是否符合 `00_文风与声口卡.md`？对手是否被强行降智？ | **S2 中度** | 强化对手的合理反制；按角色身份重写同质化对白 |
| **D6 文风与去 AI 味** | 审查 `lint_prose.py` 的候选提示及上下文；格式、套话、语感和字数是否适合本书与当前场景？ | **S2 中度** | 逐条结合叙事和人物声口判断，误报可保留或用 `--ignore` 忽略；必要时修改，勿机械删改 |

## 3. 写后状态回写清单（Post-Chapter Ledger Sync）

正文定稿后，按项目实际情况更新现有台账；可选台账缺失时根据需要形成有出处的交接摘要，不强制新建全部文件。沿用现有字段和状态语义，注明章节证据，避免覆盖上游内容：

1. **章节交接**：在已有 `追踪/章节交接.md` 或等价资料追加本章交接卡，记录可核实的章末时间、地点、人物状态、物品、信息边界与末尾 1–3 句或有上下文意义的片段；未知标记未知。
2. **`追踪/角色状态.md`**：更新本章发生变化的角色行（如伤势、关系变化、新获知的秘密、消耗的底牌）。
3. **`追踪/伏笔.md` 与 `追踪/未闭环.md`**：
   - 本章新埋下的线索，登记或更新为 `active` 并注明章节号与原文锚点。
   - 本章已兑现的伏笔或故事义务，更新为 `resolved（第XXX章）`。
4. **`追踪/世界状态变化.md`（若有）**：若本章正文已发生且能对应已有世界变化项（`Change ID`），按原有语义将其从 `planned` 更新为 `verified（第XXX章）`；不要将未发生的计划标为已验证。
5. **`正文/写作状态.md`**：更新已完成章节列表、累计净字数与下一待写章节编号。

## 4. DOCX 汇编与视觉交付规范（按需）

当用户要求将已完成的正文导出为 Word 文档（`.docx`）时：

- **纯净排版**：封面包含书名、分卷/章节范围、总字数与生成日期；内文采用规范的小说阅读排版（中文正文推荐宋体/思源宋体 11pt-12pt，首行缩进 2 字符，行距 1.35-1.5 倍，章标题清晰分页）。
- **剥离工作台痕迹**：正文中严禁出现 `RULE-001`、`CH-001`、`[待确认]` 等内部工程编号或交接卡内容。
- **渲染核验**：若有宿主文档技能（如 `word-processing`）优先遵循其规范；通用环境下使用 `python-docx` 生成后，通过 LibreOffice 转 PDF 并渲染页面预览图，确认无乱码、无孤行标题、无格式错位后再交付。
